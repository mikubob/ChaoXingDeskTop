# 桌面版使用与开发指南

**版本：0.4.2** · Windows 10 / 11 x64 · Python + PySide6 / QML · GPL-3.0

[项目首页](../README.md) · [下载安装包](https://github.com/mikubob/ChaoXingDeskTop/releases/tag/v0.4.2) · [第三方声明](THIRD_PARTY_NOTICES.md)

本文中的命令默认在 `desktop` 目录的 PowerShell 中执行。

## 安装与升级

安装包包含 Python 环境及运行依赖，默认安装到：

```text
%LOCALAPPDATA%/Programs/ChaoxingDesktop/
```

安装后可通过桌面或开始菜单快捷方式启动。升级前退出旧程序，再安装到原目录；安装器保留原 `installation.json`，沿用已有设置、账号、Cookie 和凭据。卸载保留个人数据。

如果使用完整程序目录，打开 `ChaoxingDesktop.exe` 即可。请保留 `_internal`、`ChaoxingWorker.exe` 及目录中的其他文件；后台组件由主程序启动。

## 使用流程

### 1. 账号与课程

在「课程与账号」点击「浏览器登录」完成扫码或网页登录，程序会自动获取 Cookie 并读取课程；也可手动登录或导入 Cookie。可以添加多个账号，为其设置备注，并分别保留加密会话；重启后恢复最后选择的账号。

切换账号会清空当前课程、选择及任务结果，需要重新读取课程。任务运行期间锁定账号切换。导入已绑定账号的 Cookie 时，会校验平台用户身份。

每门课程右侧显示完成章节数、总章节数和进度条。读取课程后优先显示本地进度缓存，同时在后台更新；发起查询时显示「统计中」，不会锁定课程选择。查询失败保留上次统计，后续重新读取课程会再次刷新。缓存按账号、平台用户、课程和班级隔离，保存在数据目录的 `course_progress/` 中，只含章节计数、课程标识和更新时间，可安全删除。

任务列表中经平台核验为「已完成」的章节任务，会立即写入 `task_completion/`，按账号、平台用户、课程、班级和章节 ID 隔离。下次启动仍读取章节目录以发现新增任务，但缓存已完成的任务保留真实名称并直接标记完成，跳过处理和逐章核验，从第一个未完成任务继续。未完成、已停止或核验失败的任务不写入完成缓存；仅有课程汇总统计不能据此跳过章节。任务结束后不额外启动全课程统计；未完成任务保留逐章验收和结束补查。任务缓存可安全删除，不作为讨论／活动提交凭据。

手动核验也会同步任务缓存：确认完成时保存，未取得完成证据或章节已不存在时移除对应记录；请求失败时保留旧缓存。「任务结束后追加学习次数」独立按全部所选课程执行，不受任务完成缓存影响。

如需排查平台重置任务或原章节新增任务点，可在「学习设置 → 章节检测与学习次数」开启「忽略完成缓存重新检查」。该选项默认关闭；开启后不按本地完成缓存跳过所选任务，按平台状态检查并更新缓存。检查为未完成时移除旧完成记录，请求失败则保留；关闭开关后恢复缓存续跑。开关随设置保存，保持开启会影响后续每次运行；不会强制重做平台已确认完成的章节。

首次体验可以选择「离线演示」，无需连接平台。

### 2. 学习设置与服务

在「学习设置」调整倍速、章节并发、重试和未开放章节处理策略。在「题库与 AI」配置服务顺序、凭据、查询间隔、超时和重试。

声明式 JSON 题库支持 GET / POST、题型映射和响应字段路径，不执行模板中的 JavaScript。真实服务连接测试可能消耗服务额度；图片识别需要模型支持视觉输入。

### 3. 答案处理

题库按顺序查询，AI 补全未解决的题目，人工补全处理剩余答案。随机补全默认关闭，开启后仅处理仍未解决的单选、多选和判断题。

默认只保存答案。自动提交需独立开启，并要求所有题目已有答案；仍有空白题目时仅保存。填空按真实命名空位逐一对应，多空答案使用 JSON 字符串数组。声明式题库可选 `completion_separator`（1–16 字符），仅在来源明确约定时拆分多空答案；未声明时不猜测分隔符。AI 按 `blank_count` 逐空作答，空数、布局、段数与保存响应异常分别诊断。未知 hidden/editor 映射保留待处理。

### 4. 进度与任务控制

在「任务与日志」查看章节、媒体与逐题结果。任务进度表示本轮处理进度；媒体达到时长后仍需平台确认，待核验状态不会等同于平台已完成。

「暂停后续」阻止新的调度、答题请求和写入，在途请求及当前媒体可以继续。停止先协作取消，超时后终止后台；已经送达平台的请求不会撤回。

验证码使用本地 CPU OCR。识别不可用或验证类型不支持时，相关章节保留待处理；可在平台页面完成验证后重新登录或导入 Cookie。

## 账号与本机数据

在「课程与账号」点击「浏览器登录」，程序会打开独立的 Edge / Chrome 窗口。在网页中完成扫码或账号登录，进入个人空间后，程序自动获取超星 Cookie、按账号加密保存，并验证登录和读取课程，无需手动复制。首次使用无需填写桌面端账号或密码；登录其他账号时先点击「添加账号」。已有账号只接受同一用户的会话。

此功能需要已安装 Microsoft Edge 或 Google Chrome。登录窗口使用临时独立配置和无痕模式，不读取日常浏览器的登录资料；成功、取消或超时后关闭该窗口并清理临时配置。登录期间可点击「取消浏览器登录」；若单位策略禁用本地浏览器调试，仍可使用「导入 Cookie」。

| 内容 | 位置或规则 |
| --- | --- |
| 默认数据目录 | `%LOCALAPPDATA%/ChaoxingDesktop/` |
| 首次安装的独立配置 | 默认数据目录下的 `profiles/installer-<版本>-<标识>/` |
| 设置与账号 | 当前数据目录中的 `settings.ini`、`accounts.json` |
| Cookie | 各账号独立保存，使用 Windows DPAPI 加密 |
| 日志 | 默认位于当前数据目录的 `logs/`，可在界面中修改 |
| 测试与开发隔离 | 通过 `CHAOXING_DESKTOP_DATA` 指定独立目录 |

- Cookie、题库 Token、AI Key、代理和通知凭据使用 Windows DPAPI 加密，通常绑定当前 Windows 用户与本机。登录密码不写入账号文件。
- 旧明文 Cookie 成功迁移并加密保存后删除；迁移失败时保留原文件并提示。
- **完整 INI 导出包含当前明文密码和密钥，应留在本机。** 保存失败或检测到其他进程修改时保留原文件，不覆盖更新状态。
- 日志先脱敏再显示与写盘，单文件约 10 MiB、总量约 100 MiB、保留 14 天。删除仅处理本应用命名的普通日志。
- 同一数据目录仅运行一个主窗口，重复启动会唤起已有窗口。界面日志、逐题结果及后台队列有容量限制。

## 0.4.1 填空与只读核验修复

只读核验合并界面摘要通知并增量维护统计，减少大量记录时的阻塞；后台事件按时间预算交付，保留停止与末尾事件。界面显示章节、章节／卡片读取次数、失败与耗时，局部网络失败可继续其他目标，会话或身份失效时停止。

默认「核验本人讨论／活动」复核待处理或已有关联记录的章节，可复用已观察卡号但重新读取证据；「全量发现本人记录」扫描可定位章节。未知卡数仍最多扫描 7 卡，尚未验证所有真实平台导航与 hidden/editor 保存协议。本人证据、任务点与章节状态分别判断，未决意图不会被清除。

清理无调用的 `attentionRows` 全量快照属性，使用现有 `attentionModel`；合并重复章节索引，移除图标脚本和测试中的无用导入。动态 Qt/QML 入口、worker 通知导出、打包钩子、vendor 功能、资源及全部测试保留；依赖版本未变。

新增回归位于 `tests/test_completion_verification_repairs.py`，真实 QML＋QProcess/Controller 离线压力与停止检查可运行：

```powershell
.venv-build/Scripts/python.exe tests/verification_performance_smoke.py --output build/verification-performance.json
```

## 弹框与提示（0.4.0 界面修订 1）

确认按钮使用明确中文操作名称，蓝色执行／打开、青色保存、紫色测试、红色删除／放弃，取消和关闭为次要操作；危险确认首先聚焦取消。颜色同时配合文字和提示标识，禁用按钮不使用可执行操作的颜色。

弹框内的档案、人工副本、复制操作直接显示结果；失败时保留上下文和输入，不会因提示出现在主窗口遮罩后而难以察觉。副本与摘要为空时禁用主操作，读取损坏显示红色错误；人工副本保存／未保存／约束错误分开显示。编辑器的关闭按钮会提醒未保存的改动；该提醒不代替用户主动保存，未增加自动提交或自动保存。

本轮沿用 0.4.0 版本，现有发行页附件更新为“界面修订 1”；对应修订源码由 `v0.4.0-ui.1` 标签固定。原 `v0.4.0` 标签及 GitHub 自动源码快照仍为初版，修订源码请使用发行附件的 source.zip 或修订标签。

## 0.4.0 工作台升级

- 课程底栏的「查看本轮策略」集中显示三类提交开关、隐藏的已选课程、题库顺序、AI／人工／随机与通知类型。首次使用或修改自动提交策略后确认一次；普通只保存不增加确认。确认期间账号、会话、课程或配置变化会使确认失效。
- 服务页默认显示紧凑题库列表，展开所选详情；「AI 设置」可直接进入 AI 表单。编辑、启用与排序保留输入控件。真实连接检查需主动触发，可能消耗额度；配置变化使上次检查过期。
- 「任务与日志 → 需处理」汇总章节、题目、讨论和活动的原因，可按类别与关键词筛选、键盘打开全文。聚合显示最多 2000 项／8 MiB，淘汰显示不会清除防重记录。日志默认收起，可随时展开。
- 「只读核验章节」仅使用当前已读取课程的 Cookie 会话，重新读取章节完成状态。「核验本人讨论／活动」另读任务卡与本人参与证据，分别展示本人状态、任务点和章节状态。两个入口均不生成、保存答案、提交、发布或调用活动完成回调，也不清除 unknown／intent；未找到记录不能解除重发限制。会话过期时先重新读课，不回退到密码登录。
- 「高级设置 → 导出排障配置」只导出已知布尔、枚举、数值策略和版本。地址、凭据、账号、正文和未知扩展字段全部省略；完整 INI 仍为明确标注含凭据的个人备份选项。数据说明可查看 profile、DPAPI 和备份边界。
- 「运行摘要」按账号隔离，最多 20 轮／2 MiB，每轮最多 1000 个未完成章节标题及定位；最多每 2 秒写入一次原子快照。摘要包含课程名和课程／章节标识，未加密，不保存题干或答案。「从摘要选课」先重新核实身份并读课，再选择能定位的未完成课程；不自动启动，不重放旧请求。旧摘要没有定位时仍可回看，需手动选课。
- AI 设置新增「每次操作 AI 请求硬上限」，0 为不限。一次课程运行内，连接预检、测验、讨论和活动共享上限，重试也计数；主动连接检查和预览分别为独立操作。可设服务返回 token 的累计告警（0 关闭），只告警、不阻断；缺失 usage 显示未知，不估造 token 或账单。
- 「命名 AI 档案」可把当前设置保存为默认档案，再显式切换不同地址、模型、视觉声明、请求限制与独立凭据。每个档案整份配置使用 Windows 用户 DPAPI 加密；最多 20 项／256 KiB。运行中锁定，没有自动备用提供商。删除档案保留当前已加载设置副本；完整 INI 不含这些档案，备份需保留 `ai_profiles.json`。
- 声明式题库导入先展示域名、方法、请求／响应映射和拒绝字段，校验通过后再确认替换。校验失败不能导入，不执行脚本，也不触发连接检查。
- 讨论和问卷详情可打开「编辑本地副本」；显式标记人工来源，支持按原生题目／选项 ID 修改与约束提示、版本保存、复制和导出。仅编辑已确认的本地草稿，问卷未答完整但明确保存为草稿时也可修正。原始记录、生产意图和平台状态不变。停止／异常退出后的旧显示来源、unknown／intent 和已提交记录保持只读。重启后的副本可回看导出，来源重新确认前只读。
- 人工副本在 `draft_copies/` 按账号保存，最多 20 项／2 MiB，含题目和正文、未加密。满容量不自动淘汰；可先导出，再经确认删除独立副本，删除不影响原始草稿或防重记录。当前没有副本提交入口，第二期前置合同见 [REVIEWED_SUBMISSION_CONTRACT.md](REVIEWED_SUBMISSION_CONTRACT.md)。
- 「任务与日志 → 容量」查看各显示保留／淘汰、日志积压／峰值／失败批次和导出范围。左下「版本与校验」查看运行方式和 profile、主动打开发行网页或复制不含账号／路径的版本校验说明；不自动下载、执行或宣称版本最新，也不代替实际安装包哈希核对。
- 关闭重做／追加次数时从属参数禁用且保留；保存数值、枚举或模板错误时跳转并聚焦对应文本、多行、开关或选择控件。必要灰色文字提高对比度。最小逻辑窗口仍为 980×700，高 DPI 实机与跨屏验收仍待进行。

实施验收与已知限制见 [UPGRADE_ACCEPTANCE.md](UPGRADE_ACCEPTANCE.md)。

0.4.0 清理后已通过 413 项单元、7 组界面回归、四档软件缩放、冻结 worker／GUI，以及隔离目录中的全新安装、0.3.9 覆盖升级和卸载数据保留验收。安装测试禁用注册与快捷方式；并非干净虚拟机或 Windows 高 DPI 实机验收。源码与安装包由现有 provenance 门槛绑定。

## 源码运行

开发与构建环境为 **Windows x64、Python 3.13.9**。准备运行环境：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe run.py
```

`run.py` 是主程序入口，默认启动原生 WinUI 3 界面。首次运行前安装 .NET 8 SDK 并执行 `./scripts/build-winui.ps1`。后台进程使用 `--bridge` / `--worker` 模式，保留 Python 业务层与 Qt Core 模型；文件选择和界面渲染由 WinUI 负责。原 QML 参考界面可通过显式 `--legacy-qml` 启动。[原生界面开发与构建](winui/README.md)

## 构建与发布

### 构建程序

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build.ps1 -OutputDirectory dist/release-0.4.2/ChaoxingDesktop
```

构建脚本会准备 `.venv-build`、安装锁定依赖并核对依赖闭包，随后运行单元回归、发布自包含 WinUI 3 界面、使用 PyInstaller 打包 Python 后台，最后验收冻结 worker 与原生界面。开发机还需要 .NET 8 SDK。

程序输出至 `dist/release-0.4.2/ChaoxingDesktop/`。可通过 `-Wheelhouse <绝对路径>` 使用完整的本地 wheel 目录离线安装。依赖更新需要重新生成、审阅锁文件，并在干净环境中验证。

### 生成安装包

准备 [NSIS 编译器](https://nsis.sourceforge.io/Download)，将下方路径替换为本机的 `makensis.exe`：

```powershell
.venv-build/Scripts/python.exe scripts/build_installer.py --app dist/release-0.4.2/ChaoxingDesktop --compiler "C:/Tools/NSIS/makensis.exe"
```

产物默认写入项目根目录的 `release/`：

```text
ChaoxingDesktop-0.4.2-Setup-win-x64.exe
ChaoxingDesktop-0.4.2-source.zip
ChaoxingDesktop-0.4.2-installer-SHA256.json
```

安装包包含完整程序、对应源码 ZIP、许可和第三方声明，NSIS 编译器不随包分发。生成安装包前会核对程序版本、源码与产物哈希，以及单元、worker、GUI 验收标记；跳过 GUI 的构建不能用于正式发布。修改构建输入后，需要重新构建和验收。

安装器与便携打包共用 `scripts/source_bundle.py` 的公共文件清单，仅额外收录工作台验收记录和副本提交边界合同，不收集历史计划、截图、用户数据或临时文件。升级时只删除 `scripts/retired-runtime-0.3.5.txt` 列出的具体废弃运行文件，不使用通配符或递归删除，也不删除新程序仍包含的文件。

## 讨论任务（0.3.8 新增）

在「题库与 AI → 讨论任务」启用处理，选择回复水平，并独立设置讨论自动提交。新旧配置缺省均为关闭；测验提交开关不影响讨论。运行时设置锁定，变更用于下一轮。

- 精简、中等、详细分别以 50–100、150–250、350–600 字为生成目标，复用现有 AI 地址、Key、模型、间隔和请求预算；正文上限 1000 个 Unicode 字符，超限不会截断后发布。
- 固定模式始终输出单字 `好`，不初始化或请求模型，不补字、不因失败换档；不保证任意课程都接受或得分。
- 预览仅使用输入的示例主题，前三档会请求已配置 AI 服务；固定模式完全本地。预览不读取课程、不发布。
- 关闭自动提交时保存本地草稿；在「任务与日志 → 讨论记录」搜索、按状态筛选、查看与复制正文。查看详情不会触发发布。
- 发布前查本人顶层回复并保存发布意图；独立无重试 transport 发送一次，再读回确认。跨章节、跨轮重试和重启共享话题记录，不能靠删除草稿解除发布去重。
- `discussions/` 位于既有应用数据 / 安装配置目录，按账号、课程、班级、原生空间和话题隔离。备份时应一并保留，尤其是未决发布意图。记录损坏时保留原文件并阻止新发布。

当前支持标准主站章节入口到 groupweb v3 的网页合同；旧版、镜像域和无法确认身份的结构保留待处理。图片或附件题意尚未适配时，普通档位保留待处理。字数 / 业务拒绝如实记录；审核中、响应丢失或读回未定保留发布未知，不重复试发。平台明确拒绝的记录保留待处理，当前不自动清除拒绝记录后重试。

2026-10-19 对用户选定的三个真实话题完成发布、正文读回、任务及章节确认、再次运行去重验收；使用预先审阅的正文核验协议，未调用外部 AI 服务。离线测试覆盖四档生成、异常恢复和隔离行为；不把这一条成功样例推广为所有课程 / 页面都已适配。

## 投票／问卷任务（0.3.9 新增）

在「题库与 AI → 投票／问卷」启用活动处理，分别选择选择题策略、文本策略与 AI 回复水平，再独立决定是否自动提交。默认均关闭，测验与讨论的提交开关不影响活动。

- 支持当前已核实的章节 `insertvote` 网页变体：同页纯文本单选、多选与简答／论述混合问卷。旧 questionnaire、复杂分支、矩阵、媒体题意与上传保留待处理。
- 选择题支持 AI、随机、AI 失败后随机；文本支持 AI 精简／中等／详细，或精确固定 `好`。随机 + 固定好不要求 AI，不发起 AI 连接检查。文本 AI 失败不自动切换固定好。
- 「示例预览」使用内置混合问卷；AI 策略请求当前服务，本地策略在界面内执行。预览不读取课程、不提交、不写生产去重记录。
- 自动提交关闭时仅保存本地草稿。开启后整卷校验通过才发送一次；本人已有参与、目标变化、约束不符或结果未知均不盲目重投。
- 「任务与日志 → 投票／问卷」支持搜索、按状态筛选、逐题查看与复制。来源、生成覆盖、提交确认、任务点和最终章节完成分别记录。
- `activities/` 存放本地草稿与提交意图，备份应用数据时一并保留。未知意图或损坏记录禁止新提交；不能通过换策略或重启绕过去重。

协议字段与明确边界见 [ACTIVITY_PROTOCOL.md](vendor/chaoxing/api/ACTIVITY_PROTOCOL.md)。离线验收包含 `tests/test_activity.py` 与 `tests/activity_ui_smoke.py`；冻结 worker 自检也覆盖活动模块。
